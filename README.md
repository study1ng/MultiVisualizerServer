# API 仕様書

## 1. エンドポイントとリクエスト形式

画像を読み込み、処理結果を取得するためのエンドポイントです。パスパラメータで処理条件を指定し、クエリパラメータで対象ファイルを指定します。

```http
GET /{パスパラメータ}/?{クエリパラメータ}
```

### パスパラメータ（処理条件）
`key=value` の形式をカンマ（`,`）区切りで繋いだ文字列を渡します。
**注意:** 送信する際は、この文字列全体を**パーセントエンコーディング（URLエンコード）**する必要があります。

| キー | 必須 | 値 | 説明 |
| :--- | :---: | :--- | :--- |
| `ax` | 必須 | `axial`, `coronal`, `saggital` | 断面の表示方向を指定します。 |
| `process` | 必須 | `normal` (現在)<br>`diff`, `hd` (予定) | 処理方法を指定します。現在は `normal` のみ対応。 |

**将来の実装予定（`process=diff` の場合）**
`process=diff` が実装された場合、以下のプロパティキーが追加で利用可能になる予定です。
* `src`: 基準とする `fn` のインデックス（例: `src=0` は最初の `fn`）
* `lb`: 比較対象とするラベル、または `0`（背景）にマッピングするラベル。

### クエリパラメータ（ファイル指定）
ファイルパスを指定します。複数のファイル（`fn`）を指定することが可能です。

| キー | 説明 |
| :--- | :--- |
| `base` | ベースとなるCT画像のパス（例: `/path/to/image.nii.gz`） |
| `gt` | グラウンドトゥルース（正解）ラベルのパス（例: `/path/to/gt.nii.gz`） |
| `fn` | セグメンテーションファイルのパス。複数指定可能（例: `fn=/path/to/out1.nii.gz&fn=/path/to/out2.nii.gz`） |

現在はnibabelで読み込めるファイルだけ(.nii, .nii.gz)実装済み

### リクエスト例
ベース画像、正解ラベル、2つのセグメンテーションファイルを読み込み、アキシャル面（`axial`）で通常処理（`normal`）を行う場合：

**エンコード前の概念:**
`/ax=axial,process=normal/?base=file:///path/to/image.nii.gz&gt=file:///path/to/gt.nii.gz&fn=file:///path/to/out1.nii.gz&fn=file:///path/to/out2.nii.gz`

**実際に送信するURL（エンコード後）:**
`/ax%3Daxial%2Cprocess%3Dnormal/?base=file%3A///path/to/image.nii.gz&gt=file%3A///path/to/gt.nii.gz&fn=file%3A///path/to/out1.nii.gz&fn=file%3A///path/to/out2.nii.gz`

現在はfileスキームのみ実装

## 2. レスポンス（成功時）

ファイルの読み込みに成功した場合、データ取得のための**UUID文字列**（例: `4f735879-e3c9-4e84-8311-d42473e4e252`）がテキストとして返却されます。

このUUIDを使用して、以下のURLからZIP形式の処理結果をダウンロードします。

```http
GET /{uuid}.zip
```

### ZIPファイルの構造と内容
ダウンロードしたZIPファイルを解凍すると、以下のファイル群が生成されます。

* `base.bin`
* `gt.bin`
* `fn0.bin` (1つ目の `fn` のデータ)
* `fn1.bin` (2つ目の `fn` のデータ)
* `payload.json` (現在は空)

**バイナリ（`.bin`）ファイルの扱い方:**
1.  ファイルは **DEFLATE** 形式で圧縮されています。
2.  解凍すると NumPy の `.npy` 形式（`np.save` で保存された形式）になります。
3.  Python等で `np.load()` を使用して元の ndarray オブジェクトとして読み込みます。

## 3. レスポンス（エラー時）

サーバー側で問題が発生した場合、以下の形式の JSON でエラーメッセージが返却されます。

```json
{
  "ty": "InternalError",
  "messages": [
    "requested data don't exist or expired"
  ],
  "uid": "112"
}
```

### エラーの種類 (`ty`)
すべてのエラーレスポンスで共通して `ty` と `messages` キーが含まれます。

| エラー種別 (`ty`) | 原因・説明 |
| :--- | :--- |
| `InternalError` | クライアント側の実装またはリクエスト内容に問題がある場合。 |
| `FileError` | クライアントが指定したファイルが存在しない、またはファイル読み込み中に問題が発生した場合。 |
| `ServerError` | クライアントのリクエストに関係なく、アプリケーション側（サーバー側）のフローに起因するエラーが発生した場合。 |
